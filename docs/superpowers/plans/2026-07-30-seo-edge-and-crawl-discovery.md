# SEO Edge Hardening and Crawl Discovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the security-header and crawl-discovery gaps from the 2026-07-30 SEO audit by adding Worker response headers, an XML sitemap, a repo-owned `robots.txt`, and a `noindex` on the client-rendered event shell.

**Architecture:** URL canonicalization already ships as Cloudflare Redirect Rules (deployed 2026-07-30, documented in `docs/CLOUDFLARE-DEPLOYMENT.md`), so this plan removes the now-dead Worker apex redirect and replaces its unit coverage with a live e2e spec. Response headers are added in a new `worker/headers.ts` module wrapping the `env.ASSETS.fetch` result, keeping `worker/index.ts` as pure routing. The sitemap is generated by `@astrojs/sitemap` from Astro's route manifest so it cannot drift from the pages that actually exist.

**Tech Stack:** Astro 5 (static output), Cloudflare Workers + Workers Assets, Bun, Vitest via `@cloudflare/vitest-pool-workers`, Playwright.

## Global Constraints

- Package manager is **bun**. Never `npm` or `yarn`. Add deps with `bun add`.
- Every commit follows **Conventional Commits v1.0.0**: `<type>(<scope>): <subject>`, imperative mood, lowercase start, **no trailing period**.
- Multi-line commit messages go in a file passed with `git commit -F <path>`. Do **not** use `$(cat <<'EOF' ...)` — the validator hook reads the literal shell text as the subject and rejects it.
- Stage **explicit paths** (`git add <path>`). Never `git add -A` or `git add .` — other sessions have in-progress files in this working directory.
- **Never switch branches** in this directory. No `git checkout`, `git switch`, `git stash`, `git reset --hard`, `git rebase`, `git merge`. A `PreToolUse` hook enforces this.
- Every commit must pass `bun run build && bun run test` on its own.
- Vitest only collects `worker/**/*.test.ts` and `src/**/*.test.ts` (see `vitest.config.ts`). Tests in `e2e/` are Playwright.
- Vitest runs inside **workerd**, not Node. No `node:fs`. Assert built artifacts by fetching them through the Worker's `ASSETS` binding.
- `bun run test` runs `astro build` first, so vitest always sees a fresh `dist/`.
- Live-only Playwright specs are named `*.live.spec.ts` and begin with `test.skip(!process.env.LIVE_BASE_URL, '<reason>')`.
- Site origin is `https://www.macon170.com` — already set as `site` in `astro.config.mjs`.

## Corrections to the spec

Two errors in `docs/superpowers/specs/2026-07-30-seo-audit-remediation-design.md` were found while writing this plan. This plan implements the corrected behavior.

**1. `/logo/*` must not be `immutable`.** The spec assigns `public, max-age=31536000, immutable` to both `/_astro/*` and `/logo/*`. Only `/_astro/*` filenames are content-hashed. Files under `/logo/` have stable names (`pack170-logo-512.png`), so `immutable` would pin a stale logo in every browser cache for a year with no way to bust it. This plan gives non-hashed public assets `public, max-age=604800` (7 days) instead.

**2. Three known CSP violations exist and are expected.** The spec's allowlist omits them. Report-Only mode is what surfaces them, so this is not a blocker, but the implementer should not be surprised:

- `src/components/SiteHeader.astro:19` — an inline `style="color: var(--gold)"` attribute, which `style-src 'self'` blocks.
- `src/pages/contact.astro:270` — a `<script is:inline>` block. It is `is:inline` deliberately: the Turnstile callbacks must be global before the async Turnstile script loads (see commits `da4732a`, `fc1df51`). **Do not refactor it in this plan.**
- The contact form posts to `https://cms.macon170.com`, which needs `form-action` to allow that origin. This plan's policy includes it.

Resolving the first two is a prerequisite for promoting CSP to enforcing, which is Phase 5 of the spec and out of scope here.

```typescript
// Origins the site genuinely loads from. Everything else referenced in src/ is an outbound
// anchor href, which CSP does not govern.
const TURNSTILE = 'https://challenges.cloudflare.com';
const CMS = 'https://cms.macon170.com';

const CONTENT_SECURITY_POLICY = [
  "default-src 'self'",
  `script-src 'self' ${TURNSTILE}`,
  `frame-src ${TURNSTILE}`,
  `connect-src 'self' ${CMS}`,
  // The contact form posts straight to the CMS rather than through this Worker.
  `form-action 'self' ${CMS}`,
  "img-src 'self' data:",
  "font-src 'self'",
  "style-src 'self'",
  "base-uri 'self'",
  "object-src 'none'",
  "frame-ancestors 'none'",
].join('; ');

// No `preload`. Preloading is a near-irreversible commitment recorded in browser binaries,
// and it is not needed to close the audit finding.
const SECURITY_HEADERS: Record<string, string> = {
  'Strict-Transport-Security': 'max-age=31536000; includeSubDomains',
  'X-Content-Type-Options': 'nosniff',
  'Referrer-Policy': 'strict-origin-when-cross-origin',
  'X-Frame-Options': 'DENY',
  // Report-Only until the two known inline-content violations are resolved: the inline style
  // attribute in SiteHeader.astro and the deliberately inline Turnstile callback script in
  // contact.astro. Enforcing before then would break the contact form.
  'Content-Security-Policy-Report-Only': CONTENT_SECURITY_POLICY,
};

export function withSiteHeaders(request: Request, response: Response): Response {
  // Responses from the ASSETS binding have immutable headers, so copy before mutating.
  const result = new Response(response.body, response);

  if ((result.headers.get('content-type') ?? '').includes('text/html')) {
    for (const [name, value] of Object.entries(SECURITY_HEADERS)) {
      result.headers.set(name, value);
    }
  }

  return result;
}
```

```typescript
const IMMUTABLE_CACHE = 'public, max-age=31536000, immutable';
```

```typescript
import { describe, expect, it } from 'vitest';

const ORIGIN = 'https://www.macon170.com';

async function sitemapUrls(): Promise<string[]> {
  const index = await exports.default.fetch(`${ORIGIN}/sitemap-index.xml`);
  expect(index.status, 'sitemap index must be published').toBe(200);

  const childPaths = [...(await index.text()).matchAll(/<loc>([^<]+)<\/loc>/g)].map((match) => match[1]);

    urls.push(...[...(await child.text()).matchAll(/<loc>([^<]+)<\/loc>/g)].map((match) => match[1]));

  return urls;
}
```
